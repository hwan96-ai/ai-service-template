# Portfolio Showcase Rules

## When To Use This

Use this document when writing public-facing summaries, preparing a showcase,
or evaluating whether repository content can be shared outside the private
working context.

## Separate Sanitized Repository Required

Future public portfolio or showcase extraction must happen in a separate
sanitized repository. Do not make this original repository public as the
showcase path.

The sanitized repository should contain only reviewed, intentionally public
content. It must not include local-only task files, private run artifacts,
secret-like files, customer data, internal URLs, proprietary implementation
notes, or non-public business information.

## Original Repository Handling

Treat this repository as private, restricted, or portfolio-sensitive. Keep
harness engineering changes general and reusable. Do not add project-specific
marketing claims, customer claims, operational claims, or deployment claims that
are not supported by repository evidence.

## Public Summary Guidance

Public summaries may describe the repository as a Windows/PowerShell,
preview-first AI coding safety harness if the statement remains consistent with
the current docs. Avoid details about private workflows, unreleased plans,
internal URLs, or sensitive execution context.
